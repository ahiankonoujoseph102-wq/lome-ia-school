Ce fichier donne à Claude le contexte du projet. Le lire avant toute modification.

## La personne qui porte le projet

- N'est **pas développeuse ou développeur** et travaille **uniquement depuis un téléphone**, via Claude Code sur le web.
- **Langue (règle absolue)** : toutes les réponses, tous les résumés et tous les messages destinés à Joseph (porteur du projet) sont rédigés **en français simple, sans exception** : réponses dans la conversation, résumés de fin d'étape, commentaires et descriptions de pull request, messages d'aperçu. Jamais d'anglais, même pour une réponse courte.
- Toujours expliquer simplement, en français, ce qui a été fait et pourquoi.
- Signaler clairement tout ce qu'elle doit faire elle-même : créer un compte, fournir une clé d'API, cliquer sur un bouton dans un tableau de bord, valider une pull request…
- Aucune commande ne peut être lancée de son côté sur un ordinateur : Claude exécute, vérifie et pousse tout.
- Finir chaque étape par un résumé : fait / échoué / à faire de son côté.

## Le produit

Plateforme de vente et de suivi de formations en intelligence artificielle, basée à Lomé (Togo).

- **Achat puis accès immédiat** : l'élève paie et accède tout de suite à la formation.
- **Trois formats** :
  - enregistré : vidéos intégrées (YouTube aujourd'hui) ;
  - en direct : sessions Google Meet ;
  - en présentiel : à Lomé.
- **Groupe de discussion par formation**, réservé aux acheteurs, dans le style de WhatsApp : texte, images, captures d'écran, notes vocales, vidéos courtes, fichiers. Il doit être très professionnel et confortable à utiliser, sur mobile d'abord.
- **Affiliation** : un élève gagne 10 % de chaque vente faite via son lien. Retrait par Mobile Money. Au début, les retraits sont validés manuellement par l'admin.
- **Consultation gratuite** sur réservation.
- **Tableau de bord admin** complet.
- **Paiement** : aujourd'hui, Mobile Money **manuel avec preuve de paiement** (entreprise pas encore certifiée) ; FedaPay sera ajouté plus tard.
- **Exigences** : très professionnel, rapide, pensé mobile en priorité, conçu pour convertir les visiteurs en acheteurs.
- **Langue** : français. **Monnaie** : FCFA (XOF). **Fuseau horaire** : `Africa/Lome` (UTC+0, sans heure d'été).

## Stack technique (imposée)

- Laravel 13, PHP 8.4+ (starter kit officiel Livewire, authentification Fortify).
- Livewire 4 (composants monofichiers dans `resources/views/pages`, préfixe ⚡) + Flux UI + Alpine.js + Tailwind CSS 4 (Vite, via `vite-plus`).
- Base de données : SQLite en développement (`database/database.sqlite`), **MySQL en production**. Tout le code doit rester compatible MySQL.
- Temps réel du chat : Pusher, avec mise à jour régulière automatique (sans WebSocket) si Pusher est absent ou en panne.
- Paiement : Mobile Money manuel avec preuve (étape 4) ; FedaPay plus tard, derrière la notion de moyen de paiement (`App\Enums\PaymentGateway`).
- Hébergement **définitif** : Laravel Cloud, à l'adresse **https://lomeiaschool.laravel.cloud** (décision de Joseph, octobre 2026 : plus aucun changement de nom de domaine ni de passage sur Hostinger prévu ; voir « Déploiement Laravel Cloud (définitif) »). Le code reste compatible avec un hébergement mutualisé (Hostinger) au cas où. **Pas de processus permanent** : files d'attente et tâches planifiées passent par cron (`schedule:run` chaque minute, `queue:work --stop-when-empty`).
- Fournisseur vidéo **interchangeable** : YouTube maintenant, Bunny.net plus tard.

## Conventions de code

- **Nommage** : code (classes, méthodes, variables, tables, colonnes) en anglais ; tout texte visible par l'utilisateur en français.
- **Textes d'interface** : le starter kit utilise des clés anglaises traduites dans `lang/fr.json`. Garder ce mécanisme pour ces écrans ; pour les nouveaux écrans, le français peut être écrit directement dans les vues Blade. Messages de validation : `lang/fr/validation.php`.
- **Style** : suivre le style existant ; `composer lint` (Pint) avant chaque commit.
- **Montants** : en FCFA, stockés en **entiers** (le XOF n'a pas de décimales). Jamais de float pour l'argent. Affichage : `25 000 FCFA`.
- **Dates** : l'application tourne en `Africa/Lome`. Affichage en français (`translatedFormat`).
- **Compatibilité MySQL** : uniquement via les migrations et le query builder / Eloquent. Pas de SQL brut propre à SQLite. Attention aux types (`enum` natifs à éviter, préférer `string` + enum PHP), aux index uniques et aux clés étrangères. **Noms d'index et de clés étrangères : 64 caractères au plus** (MySQL refuse au-delà, SQLite ne vérifie rien : les tests ne le voient pas) ; un nom automatique (`table_colonne1_colonne2_index`) dépasse vite : donner un nom court explicite. **MySQL n'annule pas une modification de structure** : une migration qui échoue au milieu laisse la base à moitié modifiée et la tentative suivante échoue (« Duplicate column name »). Toute nouvelle migration de structure doit donc pouvoir reprendre : vérifier avant chaque ajout (`Schema::hasColumn`, `hasTable`, `getIndexes`, `getForeignKeys`), comme `2026_10_13_100000_create_free_registration_tables` ; migration de données dans une transaction et sans doublon. Incident d'octobre 2026 : déploiement de l'inscription gratuite bloqué par un index de 65 caractères (corrigé, test `FreeRegistrationMigrationResumeTest`).
- **Services externes** derrière une interface (ex. `VideoProvider` avec une implémentation `YouTubeVideoProvider`), choisis par la configuration, pour pouvoir changer de fournisseur sans toucher au reste du code.
- **Clés et secrets** uniquement dans `.env` (jamais commités) ; documenter chaque nouvelle variable dans `.env.example`.
- **Mobile d'abord** : concevoir chaque écran pour un petit écran, puis l'agrandir.
- **Tâches longues** (e-mails, traitements de médias) : en file d'attente (driver `database`), jamais pendant la requête.
- **Tests** : un test de fonctionnalité (PHPUnit) pour chaque parcours important (achat, accès, affiliation, retrait).
- **Champs de lien de l'admin** (lien Google Meet de la consultation et des sessions, liens YouTube et Google Drive des leçons et ressources, vidéo de la page Entreprises, vidéo et lien TikTok de l'accueil, vidéo des témoignages, carte et réseaux sociaux) : toujours **nettoyés avant la vérification** par `App\Support\PastedLink` (`PastedLink::cleanRequest($request, [...])` dans le contrôleur ou `prepareForValidation()` du FormRequest) : caractères invisibles (espace insécable, largeur nulle…) et espaces retirés, lien extrait d'un texte plus long (« Rejoindre avec Google Meet : https://… »), majuscules du clavier retirées de « https:// » et du nom de domaine (jamais du chemin : identifiants YouTube et Drive), « https:// » ajouté s'il manque. `GoogleMeet::normalize`, `YouTube::id`, `GoogleDrive::fileId` nettoient aussi. Message d'erreur qui montre la forme attendue (`GoogleMeet::invalidMessage()`, `YouTube::invalidMessage()`). Dans les vues, **jamais `type="url"`** (le navigateur refuserait lui-même un lien sans https ou entouré de texte) : `type="text" inputmode="url" autocapitalize="none" autocorrect="off" spellcheck="false"` (fait automatiquement par `x-admin.field type="url"`). Même nettoyage côté navigateur pour l'aperçu vidéo (`cleanPastedLink` dans `site.js`). Tests : `tests/Unit/PastedLinkTest.php` et un test par écran.

## Comptes, rôles et accès

- **Inscription** : nom, numéro WhatsApp (obligatoire, unique, stocké au format international complet via `App\Support\PhoneNumber`, règle `App\Rules\WhatsAppNumber`). `PhoneNumber::PLANS` donne, par pays, la longueur du numéro et si le 0 initial est un simple préfixe national (France, Ghana, Nigeria…) ; en Afrique de l'Ouest il fait généralement partie du numéro et n'est **jamais retiré** (Bénin : 10 chiffres commençant par 01, un ancien numéro à 8 chiffres reçoit 01 devant ; Burkina Faso : 8 chiffres, ex. +226 07 27 63 81). ## Notes sur l'environnement cloud de Claude

- Dans l'environnement Claude Code web, les téléchargements Composer via l'API GitHub peuvent être refusés (403). Solution qui marche :
  `composer config -g use-github-api false` puis `composer install --prefer-source`.
  Le paquet `phpstan/phpstan` n'existe qu'en archive : le reconstruire depuis son dépôt git avec `git archive` et le placer dans le cache Composer (`~/.cache/composer/files/phpstan/phpstan/<sha1 de l'URL>.zip`).
- `fonts.bunny.net` est bloqué : la police Instrument Sans est donc servie en local via le paquet npm `@fontsource-variable/instrument-sans`. C'est aussi plus rapide pour les visiteurs.
- PHP 8.4 minimum (les dépendances Symfony 8 l'exigent) : sélectionner PHP 8.4 dans le panneau Hostinger.
- Hostinger mutualisé ne dispose pas forcément de Node.js : prévoir à l'étape 11 de compiler les fichiers CSS/JS ailleurs (GitHub Actions) avant le déploiement.
- **À vérifier à l'étape 11** : l'envoi réel d'une vidéo de 50 Mo dans un groupe sur Hostinger. `public/.user.ini` demande `upload_max_filesize = 64M` et `post_max_size = 70M`, mais Hostinger peut imposer ses propres limites : vérifier dans le panneau Hostinger (Avancé > Configuration PHP > Options PHP : `upload_max_filesize`, `post_max_size`, `max_execution_time`, `memory_limit`) et les augmenter si nécessaire, puis refaire l'essai depuis un téléphone.
